# 0002. 認証情報ストアはひとつ

## 文脈

jira-dash は `internal/jira` で Jira REST API を in-process で直接叩く。一方、
`cmd/jira`（`jira auth login`）は同じ認証情報を使う別バイナリとして存在する。

## 決定

認証情報は `~/.config/jira-cli/credentials.json`（または `JIRA_*` 環境変数）を
唯一のストアとし、jira-dash と `jira` CLI の両方がここから読む。

## 理由

- ストアを2つ持つと、片方だけログインし直して片方が古いままという状態になり得る。
  それを避けるために最初から1つに決めた
- もともと外部の TypeScript 製 `jira` CLI に検索・詳細取得・作成を経由させていたのも
  同じ理由（ストアを2つ持ちたくない）だった。その CLI は Go 版の自前 CLI 兼 API
  クライアント（`internal/jira` / `cmd/jira`）に置き換わったが、認証情報のストアを
  一本化する方針自体は引き継いだ
- `Searcher` インターフェースは差し替え可能にしてある。これは0001の移行で
  外部プロセス呼び出しから in-process 呼び出しへ切り替える際の緩衝材として設計した

## 結果（トレードオフ・限界）

- ファイル形式・環境変数名は外部 CLI 時代のものを引き継いでおり、jira-dash 側の
  都合だけでは変更できない
