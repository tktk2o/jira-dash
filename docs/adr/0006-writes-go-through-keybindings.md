# 0006. Jira への書き込みは作成だけをダッシュボード自身が持つ

## 文脈

課題の作成に加えて、コメント投稿・ステータス変更・担当者変更など、Jira を書き換える
操作が増えていく。それぞれを jhd 自身のコードとして実装するか、設定側のコマンドに
任せるかを決める必要がある。

## 決定

jhd 自身が Jira を変更する経路は課題の**作成だけ**に限定する。それ以外の変更は
すべて設定のキーバインド（シェルコマンド）に委ねる。

## 理由

- この方針のおかげで、コメント・ステータス・担当者の追加は `{{.Input}}` /
  `{{.Choice}}` / `choices` / `refresh:` という**枠と変数**の追加だけで済んだ。
  Jira を直接叩くコードは1行も増えていない
- 書き込み経路を1箇所に絞ることで、jhd のコード側が持つ「Jira に対して何ができるか」
  の範囲が固定され、レビューや検証の対象が狭くなる

## 結果（トレードオフ・限界）

- 新しい種類の書き込み（作成以外）は、設定側のコマンドとして表現できる形でしか
  追加できない。コマンド1本で表現できない書き込みは今の設計に乗らない
